# BullX Financial Data Agent Install Guide

You are installing the public `bullx-financial-data` skill and connecting it to a private Terminal Financial Data MCP endpoint for financial-data and market-simulator tasks.

Follow this separation strictly:

- Public skill files teach routing and tool-use rules.
- Private Terminal values configure the local MCP instance.
- Never write a real endpoint, API key, filled `Authorization` header, or user-specific secret into this repository, a shared skill, a report, or a commit.

## Required Private Values

The Terminal API Key page should provide these values:

```text
process.env.BULLX_FINANCIAL_DATA_MCP_ENDPOINT="<terminal-origin>/api/v1/financial-data/mcp"
process.env.BULLX_FINANCIAL_DATA_MCP_API_KEY="<user-api-key>"
```

Persist them in the target agent's supported environment-variable mechanism or secret store. If the target agent does not expand environment variables inside JSON/YAML MCP headers, put the final `Authorization` header in that agent's local secret/header store, not in the public repository.

## Install The Skill

Install or enable this repository as the `bullx-financial-data` skill. If the target agent does not support skills, load `SKILL.md` as persistent routing instructions and still register the MCP server below.

The expected MCP server name is:

```text
bullx-financial-data
```

## Register The MCP Server

Use Streamable HTTP transport. Generic HTTP MCP clients that require manual headers need:

```text
url: ${BULLX_FINANCIAL_DATA_MCP_ENDPOINT}
Authorization: Bearer ${BULLX_FINANCIAL_DATA_MCP_API_KEY}
MCP-Protocol-Version: 2025-11-25
Accept: application/json, text/event-stream
```

For Codex CLI, prefer:

```bash
codex mcp add bullx-financial-data --url "<terminal-origin>/api/v1/financial-data/mcp" --bearer-token-env-var BULLX_FINANCIAL_DATA_MCP_API_KEY
```

Do not manually add `MCP-Protocol-Version` in Codex `http_headers`. Codex sends MCP transport headers during protocol negotiation; adding a fixed value can produce a merged duplicate header such as `2025-11-25, 2025-06-18`, causing `tools/list` startup failures. If an existing Codex config has this header, remove it and restart Codex discovery.

Make sure `BULLX_FINANCIAL_DATA_MCP_API_KEY` is exported in the shell or launcher that starts Codex. A value stored only in a project `.env.local` file is not visible to Codex unless the launcher loads it.

Choose the template that matches the target agent:

- Codex: `agents/codex.mcp.template.toml`
- OpenAI/Codex metadata: `agents/openai.yaml`
- Claude Code: `agents/claude-code.mcp.template.json`
- Kimi CLI: `agents/kimi.mcp.template.json`
- OpenClaw: `agents/openclaw.mcp.template.json5`

For local installation, copy the matching template into the target agent's local config location and replace placeholders with the private values supplied by Terminal. Keep the repository templates unchanged.

## Use The Skill

Use BullX MCP for:

- A-share symbol resolution, fuzzy stock lookup, and pinyin/name matching.
- Point-in-time A-share stock and index universes for screening, validation, backtest inputs, and data-quality checks.
- Trading calendar, latest tradable date, and session checks.
- Daily bars, latest daily snapshots, historical A-share stock minute OHLCV, and supported aggregations.
- Market breadth, market temperature, advance/decline counts, and intraday trading-activity proxies.
- Realtime A-share stock quote snapshots.
- Factor snapshots, valuation, liquidity, capitalization, and moneyflow.
- Index profiles, daily bars, constituents, weights, and quotes.
- ETF/LOF/exchange-traded fund quotes, single-fund minute/daily bars, batch ETF minute/daily OHLCV, public mutual fund profiles, and fund holdings.
- Macro or industry-economics indicator resolution and time series.
- Financial statements, indicators, fundamentals, shareholders, and risk/compliance facts.
- Listed-company announcements, filings, and announcement details.
- BullX parameter dictionary and industry-code decoding.
- Accessible simulator accounts, current holdings, holding-change events, and daily performance.
- Explicitly requested private simulator creation and target-weight rebalancing when the API key has simulator write permission.

Current reference manifest: `2026-07-15.3`, 37 registered public tools. `tools/list` is scope-filtered: financial-data-only keys see 31 tools, simulator-read keys see 35, and simulator-read-write keys see all 37. If the visible count differs from what the key scopes should expose, trust the runtime surface for that session and mention the mismatch.

Before drawing conclusions, inspect `warnings`, `sources`, `meta`, row counts, date fields, freshness, adjustment basis, and partial-result indicators. Treat current-day stock daily snapshots as daily snapshots, not stock minute bars. Treat intraday activity as a turnover/return proxy, not real-time moneyflow, main-fund inflow, or northbound flow. Treat Quant-backed OHLCV tools as overnight batch-updated historical data; for latest price or realtime percent change, use the stock realtime quote or fund quote tools instead.

## Market Simulator Contract

- Use `bullx_market_simulator_list_accounts` to discover accounts readable by the API-key user: owned, public under Terminal's existing rule, or published ITBT accounts. Use the detail tools for synchronously refreshed facts.
- Use `bullx_market_simulator_get_current_holdings`, `bullx_market_simulator_get_holding_changes`, and `bullx_market_simulator_get_performance` for holdings, buy/sell/T+1/corporate-action events, and the daily equity/return curve. Inspect `data_as_of` and `calculated_at`.
- Never send `userId` or `user_id`. Inaccessible accounts return `NOT_FOUND`, and public or ITBT visibility never grants write access.
- Use `bullx_market_simulator_create_account` only for an explicit request. Supply `name`, numeric `initial_cash`, one zoned `buy_time`, and `initial_positions[{symbol,target_weight,buy_price}]`; weights and prices are JSON numbers, and quantities are not accepted. The server validates the time and prices with simulator trading rules, rounds down to whole lots after fees, keeps residual cash, and creates a private account for the API-key user.
- Use `bullx_market_simulator_rebalance_account` only for an explicit request on the API-key user's private simulator. Supply `account_id`, a zoned `rebalance_time`, and `target_positions[{symbol,target_weight,price}]` covering the full union of current and target symbols; weights and prices are JSON numbers, and `target_weight=0` exits a symbol. The server validates the time and prices, derives quantities, and executes sells before buys.
- Simulator writes are not idempotent. Do not send `expected_plan_hash` or `idempotency_key`. After a timeout or ambiguous error, read back accounts and trade-derived holding changes before retrying; an error does not prove that no write committed.
- Successful writes expose `meta.mutation_source="mcp"`, the account ID, and trade IDs. On write errors, inspect `meta.mutation_committed` and any durable IDs before retrying. Keep request IDs, warnings, and sources when reporting the result.
- For scheduled event-impact analysis, combine simulator holdings with announcement, risk/compliance, fundamentals, and market-data tools. Scheduling and impact reasoning remain the external agent's responsibility.

## Verify

After configuring MCP, restart or refresh the target agent's MCP discovery.

Then verify:

1. `initialize` succeeds.
2. `tools/list` returns the `bullx_*` tools permitted by the key: 31 for financial data only, 35 with simulator read, or 37 with simulator read and write.
3. `resources/list` and `prompts/list` may return empty lists. This is expected because BullX financial data is exposed through tools.
4. A low-risk read-only call, such as a China A-share trading-calendar query, succeeds.
5. If simulator tools are missing, check the key's simulator scopes. If a tool call fails, check endpoint reachability, API key status, protocol headers, and whether the agent process actually received the environment variables.
